# AR Backend

Backend لشبكة اجتماعية جزائرية، مبني بـ Node.js وPostgreSQL وRedis فقط.
يشمل: مصادقة متقدمة، صلاحيات ديناميكية (RBAC)، تحقق بخطوتين، رسائل
فورية عبر WebSocket، بحث نصي، وفلترة محتوى.

## قرار معماري مهم

هذا المشروع مبنٍ عمداً على خدمة Node.js واحدة (بدل خدمات Go وRust
وMeilisearch وPrometheus/Grafana منفصلة) لسببين: تبسيط الصيانة، وإمكانية
تشغيله بالكامل على استضافة مجانية واحدة. الوظائف التي كانت بتلك
الخدمات موجودة الآن داخل نفس عملية Node.js:

| الوظيفة | كانت بـ | أصبحت بـ |
|---|---|---|
| WebSocket الفوري | خدمة Go منفصلة | `src/modules/websocket/server.js` (مكتبة ws) |
| التشفير (AES-256, X25519, Argon2id) | خدمة Rust منفصلة | `src/modules/ai-filter/security.client.js` (وحدة crypto المدمجة + مكتبة argon2) |
| البحث النصي | Meilisearch | PostgreSQL مع امتداد pg_trgm |
| المقاييس | Prometheus + Grafana | عدّادات داخلية بالذاكرة، تُعرض بمسار `/api/health/metrics` |

## التشغيل المحلي (Docker)

```bash
cp .env.example .env
# عدّل القيم بـ .env، بالذات كل ما كتوبة CHANGE_THIS

docker-compose up -d --build
docker-compose exec api npm run seed
```

## التشغيل على استضافة مجانية (بلا Docker)

راجع القسم الخاص بالاستضافة المجانية أدناه. الفكرة العامة: قاعدة بيانات
Postgres مُدارة (مثل Neon) + Redis مُدار (مثل Upstash) + تشغيل
`node src/index.js` على منصة تدعم عملية Node.js واحدة تستمع على
منفذ HTTP (Render أو ما شابه).

## المصادقة والأمان

- كلمات المرور: Argon2id حصراً (لا bcrypt، لا MD5/SHA)
- قياس قوة كلمة المرور: zxcvbn، لا يُفرض شكل معيّن لكلمة المرور
- Password History: يمنع إعادة استخدام آخر N كلمة مرور (رقم من System Settings)
- التحقق بخطوتين: TOTP (Google Authenticator) + 10 أكواد استرجاع
- Account Lock: قفل تدريجي بعد محاولات فاشلة متكررة
- رسالة خطأ دخول موحّدة (لا تكشف إن كان البريد موجوداً أو كلمة المرور خاطئة)
- كل عملية إدارية تُسجَّل بسجل تدقيق كامل (before/after)

## نظام الصلاحيات (RBAC)

صلاحيات دقيقة (`users.ban`, `posts.delete`...) مرتبطة بأدوار قابلة
للتعديل من قاعدة البيانات، بدل أدوار ثابتة بالكود. أول Owner يُنشأ
حصراً عبر `src/scripts/seed-owner.js` (يُشغَّل بـ `npm run seed`) من متغيرات `.env`، ولا يمكن إنشاء
Owner ثانٍ (قيد فريد على مستوى قاعدة البيانات).

## System Settings الديناميكية

أي رقم قابل للتغيير (مدة قفل الحساب، صلاحية OTP، الحد الأقصى للحسابات
لكل بريد...) مخزَّن بجدول `system_settings`، ويُقرأ عبر `config/settings.js`
مع ذاكرة تخزين مؤقت بـ Redis، بدل كتابته مباشرة بالكود.

## ما تم إنجازه بهذا الإصدار (تحقّق فعلي، ليس افتراضاً)

كل ما يلي جُرِّب فعلياً بخادم PostgreSQL وRedis حقيقيين محلياً، عبر
طلبات HTTP حقيقية، وليس فقط فحص syntax:

- التسجيل الكامل: أسماء محجوزة، حد 3 حسابات لكل بريد، zxcvbn، Argon2id، Password History، معرّف داخلي `AR-XXXXXXXX`
- الدخول: رسالة خطأ موحّدة، قفل تدريجي، ربط 2FA/كود الاسترجاع، كشف جهاز جديد (ببصمة subnet لا IP كامل)، إلغاء طلب حذف الحساب تلقائياً
- فحص اسم المستخدم اللحظي (متاح/مستخدم/محجوز)
- تغيير كلمة المرور (مع رفض عبر Password History)
- نسيت كلمة المرور (روابط إعادة تعيين، كانت مبنية بلا ربط، رُبطت الآن)
- الحظر بين المستخدمين + تأثيره على المتابعة والرسائل
- نظام Queue خفيف فوق Redis (بلا BullMQ لتفادي تعارض peer dependency) لإعادة محاولة إرسال البريد تلقائياً بفاصل زمني تصاعدي عند الفشل
- دخول الأدمن + صلاحيات RBAC + الأقسام المعزولة الثلاثة (Web/Android/iOS) بكود منفصل لكل قسم + سجل كل محاولة فتح

### أخطاء حقيقية عُثر عليها وصُحِّحت أثناء هذا التحقّق

- BRPOP (أمر حاجب) كان يشارك اتصال Redis نفسه مع باقي أوامر الطابور، فيجمّد كل شيء حتى تنتهي مهلة الانتظار - أصبح له اتصال مستقل
- `sendEmail`/`sendWelcomeEmail` كانتا تبلعان الخطأ بصمت، فلا يكتشف نظام Queue الفشل لإعادة المحاولة - أصبحتا ترميان الخطأ
- `req.path` داخل middleware مربوط بـ`app.use('/api/', ...)` يفقد بريفكس `/api`، فكانت مقارنة مسار الداشبورد تفشل دائماً - استُبدلت بـ`req.originalUrl`
- الموجّه القديم `/api/admin` (مسجَّل بلا صلاحيات محدَّدة) كان يعترض كل مسارات `/api/admin/*` الجديدة قبل وصولها لموجِّهاتها الفعلية بسبب ترتيب التسجيل بـExpress - أُعيد ترتيب التسجيل
- `seed-owner.js` كان خارج `src/`، فلا يصل لـ`node_modules`، وحتى غير موجود داخل حاوية Docker أصلاً - نُقل لداخل `src/scripts/`
- ملف `otp.service.js` كان مكرَّراً وميتاً (غير مربوط بأي مسار) - حُذف
- بصمة الجهاز كانت تستخدم IP كامل بدل subnet، مما يسبب تنبيهات كاذبة على شبكات الجوال - صُحِّحت

### الحدود المتبقية، بصراحة

- تشفير `email`/`bio`/`location` عند التخزين (كما ورد بالمواصفة الأصلية) لم يُنفَّذ فعلياً: يتطلب تعديل كل استعلام دخول/بحث بالمشروع الذي يطابق البريد كنص عادي مباشرة، وهذا تغيير كبير الخطر بلا مقابل واضح ما دام البريد غير معروض للعامة. قسم "الوصول المعزول" الجديد يوفّر الضبط الأمني المهم فعلاً (عزل كامل + تسجيل كل محاولة) بلا تشفير العمود نفسه
- تدقيق `await` تم على كل الوحدات المبنية بهذا الإصدار وبإصدارات v3 السابقة؛ لم يُعَد فحص كل سطر بوحدات post/feed/media القديمة كلمة بكلمة، رغم أن الفحص الآلي الذي أُجري لم يُظهر أي حالة مشتبه فيها بها

## ملاحظة على الأسلوب

كل رسائل الاستجابة، رسائل البريد، والسجلات مكتوبة بلا أي رموز تعبيرية
(إيموجي)، بصيغة مباشرة وواضحة.
